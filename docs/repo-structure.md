# Repository Structure

Prosodeus is a Bun workspace with application shells in `apps/*` and reusable product code in `packages/*`. Package names are public contracts; folders inside a package are implementation boundaries.

## Package Boundaries

```txt
apps/app                Vite + React frontend
apps/worker             self-hostable API: Hono, Postgres, Durable Objects (see docs/deployment.md)
apps/desktop            Electron shell wrapping the app build
packages/core           analysis engine, taxonomy, rewrite policy, model routing, storage primitives
packages/shared         API and WebSocket clients, transport payloads, compatibility re-exports
packages/mcp            MCP server surface built on the core engine
packages/cli            CLI entrypoint over the core engine
hitlists/               phrase lists with tiers (generated by scripts/ingest-llm-markers.py)
instructions/           rewrite guidance for each hit-list category
plugins/prosodeus       Claude Code and Codex plugin (skills + MCP config)
```

Allowed dependency direction:

```txt
app -> core, shared
worker -> core, shared
desktop -> core, shared
shared -> core
mcp -> core
cli -> core
core -> external libraries only
```

`packages/core` must not import `@prosodeus/shared`. Shared may import core domain types and re-export them for compatibility.

## Core Subsystems

`packages/core/src` keeps only public entrypoints and top-level contracts at the root:

```txt
browser.ts              browser-safe public entrypoint
index.ts                default public entrypoint
node.ts                 Node/Bun public entrypoint
types.ts                shared core domain types
```

Implementation code belongs in the subsystem that owns the behavior:

```txt
analysis/               document analysis, windows, profiles, hot sentences, style guides
classification/         LLM classifiers, gate/medium tiers, classify pipeline, heuristic screen
models/                 provider/model routing, Codex/Moonshot config, model adapters
reporting/              HTML report rendering
rewrite/                rewrite engine pieces, PCE, suggestions, validation, rewrite policy
runtime/                cross-runtime orchestration over injected dependencies
storage/                caches, document store, DB schema/adapters
taxonomy/               pattern registry and pattern metadata
text/                   splitting, text metrics, ProseMirror text extraction
```

## Import Rules

- Apps import package entrypoints only: `@prosodeus/core`, `@prosodeus/core/browser`, `@prosodeus/core/node`, `@prosodeus/shared`, or `@prosodeus/shared/browser`.
- Do not deep-import `packages/*/src` from apps.
- Do not put Node-only exports in `packages/core/src/browser.ts`.
- Keep runtime-specific dependencies at entrypoints or injected through `EngineContext`.
- If a type is part of engine behavior, define it in core and re-export from shared only when transport/UI compatibility needs it.

Run `bun run check:boundaries` after structural changes. The root `bun run test` and `bun run ci` commands include it.

## Tooling

- **Bun** is the package manager (pinned via `packageManager` in the root `package.json`) and test runner (`bun test`).
- **Turborepo** orchestrates workspace tasks. Root `build`/`test`/`typecheck` fan out via `turbo run`; root-scoped tasks (`check:boundaries`, root `scripts/` typecheck, lint) run once via `//#` tasks in `turbo.json`. `bun run ci` is the full pipeline and is exactly what GitHub Actions runs.
- **Biome** is the repo-wide linter and formatter (`biome.json` at root; no per-workspace lint configs). Some React/a11y rules are downgraded to warnings pending a dedicated cleanup pass.
- **TypeScript**: every workspace has a small `tsconfig.json` extending the root `tsconfig.base.json` and a `typecheck` script. There are no project references — internal packages are consumed **as source** (`exports` maps point at `src/*.ts`), resolved by Bun on the server and by Vite in the browser.

### Vite alias / exports sync rule

`apps/app/vite.config.ts` hard-codes aliases for `@prosodeus/core/browser` and `@prosodeus/shared/browser` to `../../packages/*/src/browser.ts` so Vite resolves subpath imports to source. These aliases must stay in sync with the `exports` maps of `packages/core` and `packages/shared`. Because package source is typechecked under each consumer's globals (workers-types, node, DOM), shared client code should depend on structural types rather than ambient globals (see `ws-client.ts` / `api-client.ts`).
